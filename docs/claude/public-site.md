# Public site (spec 013)

Detail moved out of CLAUDE.md (2026-11-02, the file passed Claude Code's size limit). Keep this file current when the feature changes.

A public, read-only website about his simulated life (Cloudflare Pages, separate repo `../karyasthan-site`). The bot **pushes** a filtered `public.json` to R2; nothing on this machine is reachable from the internet. Design: `specs/013-public-site/{spec,plan}.md`, `contracts/public-json.md`. Inert until the `public-site` skill is on.

- **Two-layer filter, fail closed** — `src/life/publicView.js` (imported by the life facade only; facade `publicRaw()`): only self/owner-origin events with no real-person subject, not redacted/reverted/rewound, not heavy and no heavy event in the cause chain (≤ 20 hops; unreadable → heavy); a chat-origin or subject span becomes ONE `out` row (time span + person ref, no kind/venue/chat); everything else from chats is dropped; a heavy stretch is one flag (`hardStretchLine` on the site); arcs and relationship changes touched by a heavy event are left out (public metrics = today's minus heavy deltas), sick blocks show as rest, and journal nights from 2 days before to 31 days after a heavy onset are never published or exported. It reads no decision leans, claims, tray, proposals, journal, narration, digests or phone checks (018: money events only for the `wallet` section, under the same filter — see "His wallet"); `now.vitals` carries every vital (body 0–100, mood −100…100, arousal, sleep debt hours, money balance; owner decision) but never sickness or the chat-mood overlay. `src/public/` (the exporter; imports only the life facade, `memory/db|identity|relationshipStore`): resolves person refs to opted-in display names or "a friend", salted ids (`p_/c_/a_/d_` + 10 hex), drops every home-like place (his home, kind `home`, a name with "home"; a place in the 0.01° cell of any home — current, former, pending, kind `home` — is listed without a pin), snaps other places to 0.01° cell centres, builds labels/stats/the weekly recap in code, then every string → `scrub.js` and the document → `schema.js` (closed keys, caps, grid, ≤ 512 KB, every string re-scrubbed). A failure → no upload (the last good snapshot stays up), a codes-only `evt:'issue'`.
- **Scrubber** — NFKC first; JIDs/@digits, phone-like runs in any script's digits (dates/times masked first), URLs, emails, group subjects (≥ 8 chars, as phrases), a real full name anywhere, a real first name (≥ 3) as a capitalized or caseless-script word, a known first name (≥ 4) with a suffix glued on ("Sanjunte"), spaced-out letters; exempt: persona names/aliases, cast names (first name only as itself), opted-in display names. A salted **purged-name guard** (`public_state.nameGuard`, keys only) keeps every real name ever seen refused after its person is purged (purge deletes the `people` row before hooks run). Since batch 3: every other word of a real name (`utils/nameTokens`: "K Ann" → anu, "Rahul Varnell" → varnell), capitalized or caseless and whole-word, is `real_name_token` unless it is a word of a persona / cast / opted-in or place name of the document (`makeScrubber({placeNames})`); `clean()` drops the string, `validate()` lists it under `soft` (never a failed export — a full / first real name still fails it as before).
- **Export** (`src/public/index.js`) — every `PUBLIC_SITE_INTERVAL_MINUTES` while the skill is on (unref'd timer; each tick checks the skill), one at a time: build → validate → `data/public/public.json` (0600) → R2 SigV4 PUT (`r2.js`, no SDK) only when the content differs from the last one uploaded (a failed upload is retried next tick) or ≥ 30 min since the last upload, never under `DRY_RUN` → pull vote tallies. `publicRaw`'s since-genesis reads are strict (≤ 2000 pages ≈ 1M rows per typed read); past that the export stops with status `history_too_large` (issue + Public page note), never an incomplete snapshot. Owner changes (opt-in, journal) export ~5 s later. An opt-out, purge of a shown person or unpublish raises a durable **privacy refresh** (`public_state.mustRefresh`): skill on → export at once (after any export already in flight lands; only its own upload counts), else (build/upload failed, or skill off) take the site offline; retried every tick until it succeeds; cleared only while it is still the request that run served (each request has its own id), so one raised mid-upload is served next, never dropped; shown on the Public page. `takedown()` uploads `{v, offline:true, generatedAt, fiction}`.
- **Real people** — opt-in per person (`public_people`, off by default; person page PUBLIC SITE switch + display name; random `f_` ids). Opt-out → gone from the next export everywhere (the site renders only the latest snapshot). `purgePerson` deletes the row (006 `onPersonPurged`).
- **Journal** — Life · Journal PUBLISH freezes a night's **self** part (never chat parts) into `public_journal`, scrubbed at publish and on every export; every venue name ever recorded becomes its kind word ("a cafe") at publish and again in every export (`life.venueKindWords`, the exporter's `deps.venueWords`; a failure fails the build — 014 §8) (`POST /api/arcs/journal/:night/publish|unpublish` in `routes/arcs.js`, the only route allowed to read the journal; audited `public.journal.*`).
- **Votes** — open Ask-me cards (not invitations, adopted or heavy; self/owner origin) are exported with code-built options; the votes Worker (site repo) counts them; the bot pulls tallies (`votes.js`, only ids/options it exported) into `public_votes`; `GET /api/arcs/cards` adds `audience` to open cards (Life · Pending shows "AUDIENCE · … a suggestion only"). Nothing is ever applied.
- **Dashboard** — `#public` (`pages/public.js`, Control): status, the exact JSON, named people, EXPORT NOW (2/min), TAKE OFFLINE (confirm). Routes `routes/publicSite.js`: `GET /api/public/{status,preview,people,people/:jid}`, `POST /api/public/{export,takedown}`, `PUT /api/public/people/:jid` — 10/min, readonly + CSRF, audited `public.*` with ids only.
- **Owner steps before going live** — R2 bucket (public read) + a bucket-scoped write token in `.env`, `npx wrangler login`, deploy the site + Worker from `../karyasthan-site` (its README), then switch the skill on.
- **The feed (plan 020)** — four optional keys beside `"v": 1`, each with its own schema number; the site's proposal is `docs/plan-020-feed-proposal.md` on the site repo's `redesign-020` branch, and `standing` is phase 4 (rows ready: `life.publicStanding()` + `build.js buildStanding`, not wired into `build()` yet; see `docs/claude/relationship-memory.md`). Same road as `phone`: `publicView` lists ids and codes under the fail-closed rule, `index.js feedRows` joins the words, `build.js buildFeed` runs every string through venue words, the home and region check and the scrubber, and `schema.js feedRules` refuses what the schema language can't. A read that fails leaves that key out; a row that fails a check is dropped, never the document. A hard stretch or a heavy onset's window means nothing in any of the four. The mind reaches the exporter through life's `stances` provider (`life.publicMind`): `src/public` imports no mind.

```jsonc
"live": null | {                 // + "liveSchema": 1. null: not out with fictional cast (nothing on, a chat's, a real person's, heavy)
  "at": 0,                       // the export tick
  "startAt": 0, "until": 0|null, "placeId": "p_…"|null,   // null at a home
  "with": ["c_…"],               // 1–4, cast of this document
  "phase": "arriving|settling|main|lull|winding|leaving",
  "line": "…",                   // ≤ 160, code-built, without the place (the site has it by id)
  "beats": [{ "at": 0, "text": "…" }]   // ≤ 6, ≤ 120 each, oldest → newest, code-built; a real chat is only "his phone buzzed"
}
// A private session: { "at": 0, "startAt": null, "until": null, "placeId": null, "with": [], "phase": null, "line": "out", "beats": [] }. The word "out" is reserved for it.
"thoughts": [{ "id": "t_…", "at": 0, "kind": "stream", "text": "…" }]   // + "thoughtsSchema": 1. ≤ 40, ≤ 80 chars, newest first. His own, resting only on his own events, never `wordless`, never what drove them. No `about` yet, and "real" is F3.
"dreams": [{ "id": "dr_…", "night": "YYYY-MM-DD", "at": 0, "recall": "vivid|fragment", "tone": "pleasant|neutral|anxious|nightmare", "text": "…", "with": ["c_…"], "placeIds": ["p_…"] }]
                                 // + "dreamsSchema": 1. ≤ 14, newest first; vivid ≤ 600, fragment ≤ 160; with / placeIds ≤ 3, may be empty. A dream naming someone who has left is left out; a vivid one waiting for its words isn't listed yet.
"mind": { "interests": [{ "topic": "…", "value": 0.72, "trend": "up|down|steady", "why": "…", "since": 0 }],
          "opinions":  [{ "topic": "…", "stance": -0.4, "trend": "…", "why": "…", "since": 0 }] }
                                 // + "mindSchema": 1. ≤ 12 each, strongest first; absent with nothing to say. Only rows no chat and no real person shaped, no people. `why` is code words from the strongest evidence, or "how he's always been".
```
  `live.at` moves every tick, so the document uploads each export while he's out.
