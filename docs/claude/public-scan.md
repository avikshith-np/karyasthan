# The public scan (scripts/public-scan.js)

A guard to run before anything goes to a public remote: it reads git blobs, not the working tree, and looks for this install's private words and for shapes that shouldn't be published. It prints a label, a path and a count, never what matched. Exit 0 clean, 1 on a hit, 2 when it couldn't check (a bad ref, an unreadable source). Test: `npm run test:public-scan` (a scratch repo with invented sources).

```bash
node scripts/public-scan.js                  # the tree at HEAD
node scripts/public-scan.js <ref>            # the tree at a ref
node scripts/public-scan.js <a>..<b>         # every blob and commit message in a range
node scripts/public-scan.js --all            # every blob and commit message on every ref
node scripts/public-scan.js --pre-push       # git's pre-push stdin: what this push adds
node scripts/public-scan.js <ref> --db <file> # also a database, opened read only
```

As a hook: `cp scripts/hooks/pre-push "$(git rev-parse --git-common-dir)/hooks/pre-push"`, once per clone (git doesn't carry hooks). It reads the main checkout's persona, world and arcs files and its database when there is one; a hit, or a source it can't read, stops the push, and `git push --no-verify` is the way past it. A repo with no sources of its own (a clean public copy) names the install that has them, once per clone: `git config publicScan.home /path/to/install`, or `PUBLIC_SCAN_HOME=` for one push. The scanner, sources, private words and database then all come from there, and any of them missing stops the push. A worktree has no `persona.json`: pass `--sources <install>/src/personality`, and `--strict` makes a missing source an error instead of a note.

- **Words** come from the install's gitignored `persona.json`, `world.json` and `arcs.json`: `name` (each word of a person, place, region or employer, less a list of generic words, the example files' words and the project's own name), `story` (a whole line of the cast's history, status and the like, 24 characters or more, in any file, which is how a fixture copied from the live story shows), `coordinate` (a place's latitude or longitude, to two decimals). A language isn't one: language features are in the code on purpose.
- **`--db <file>`**, opened read only (needs `better-sqlite3`), adds what only the database knows: `contact-name` (each word of a push name, real name, nickname or sender name), `group-name` (the whole name), `contact-id` and `group-id` (the digits of a phone, JID or LID, written any way, a phone with or without its country code), `message-text` and `story-text` / `memory-text` (a line of 25 or more characters of what a person wrote or quoted, a text, scene, journal part or memory; the bot's own messages aren't read, sent or quoted back, since many are this code's templates, a quoted line the bot also sent isn't one either, and a media message whose whole text is a `[placeholder]` holds nobody's words; exact in any case and spacing, inside a quoted string too; kept as hashes in memory, so a part of a line isn't found), `story-name` and `coordinate` (the cast and places the Director added, from the log). The last lines count what it read; `--strict` makes a database with no contacts or messages an error, and a database without this project's tables is always one. Allow about 150 bytes a message line of memory.
- **What it says about a hit:** label, path, count and where the word came from (`people#12`, `messages#88`, `world`): a row to look up yourself, not its content, and the last lines list every such row once. A plain word that happens to be someone's name is a hit: if it really is ordinary, say so with `!word` in the private-words file. A line of text that isn't anyone's words and can't be told apart in code: `!row:messages#331`, which leaves that row out, says so in the counts, and still finds the same line in another row.
- **Anything else private** (the owner's own number, say) goes in `data/private-words.txt` (gitignored, or `--words <file>`), one word or phrase a line. `!word` there says a word from the sources is ordinary, so no tracked file has to name it.
- **Shapes**: API keys, private keys, password hashes, an R2 account's endpoint, IP addresses, Tailscale hosts, emails (JID and example domains pass), `/home/<user>` paths, phone numbers of 10 or more digits. The list of plainly invented numbers is `FAKE_NUMBER` in the script: the 555 range, a run of zeros or of one digit, counting, timestamps. A test wanting a number that looks real should use one of those. An address passes only as loopback, a documentation range (`192.0.2.x`, `198.51.100.x`, `203.0.113.x`, `2001:db8::`) or from the short lists `IPV4_OK` / `IPV6_OK`: the start of a range code names by CIDR, and the samples the SSRF tests use.
- **Not read:** `package-lock.json` and `vendor/`, binary blobs (counted in the last line). Author and committer emails get a note in a range: they are the git identity, not content.
- **A path** is checked too, and one holding a private word prints as its blob id.
