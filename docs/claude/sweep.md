# The nightly sweep and thought vs deed (plan 020, E1 + F1)

Every bug a human catches becomes a permanent check. Design: `specs/020-living-being/plan.md`. Keep this file current when the feature changes.

## The sweep

- **Rules** — `src/life/sweep.js`, pure, imported by the life facade alone; `src/life/decisionLog.js` (shared with thought vs deed) folds decisions from the log, since the projection prunes closed ones. Each rule returns findings `{fp, rule, severity high|warn|info, at, eventIds, text}`; `fp` = sha of the rule + its events, so the same hole on two nights is one finding. Text is code-built plain words: no chat text, no JID, no real name; a chat's plan is only "a plan from a chat". Reverted, rewound and redacted events never count.
- **The rules**: `spend_once` (one start charged twice, or the same block started twice with both charges standing; a first start rewound away makes the second charge legitimate), `salary_once`, `recurring_once` (a `period` on rent / bills / the weekly basket), `wallet_money` (itemized money only, from `wallet.started`; an owner `set` is absolute; anchored at the window's first money event, tolerance 1), `scene_own_decision` (the scene's `decisionId` vs the block's `planBlockDecision`, or a decision for another place), `text_plan` (every plan agreed in texts hangs off a live text; a turn that plainly says a meeting is on, with no plan or meeting near it, is read against the plan step's ring: a logged reason is an answer, a step that couldn't decide is info, one that never looked is warn), `two_places` (trip, activity and sleep overlaps ≥ 5 min on real ends — `activity.ended` names its start; a re-anchor closes what was open; a teleport with no trip is info), `phone_with_someone` (an organic out text while he is with someone, or a text between them either way; a text the engine sent before it knew the outing had started is tick lag, not a finding), `go_happened`, `interview_attended` (one rule shape, "a committed go has an activity or an expiry": first by the event's own `decisionId` or the plan block, then by place and time; a go with no place is never checked, the pulse doesn't move him for it), `scene_afterwards`, `open_promise` (plan 020 D3: a commitment past its time with no outcome, read from the commitments view; a go with a place is `go_happened`'s and isn't said twice; a text that named a day, or a commitment with nothing to check it by, is info).
- **What it can't see** (also in the Life · Now guide): `text_plan` can only say "may be a refusal" for a turn older than the plan step's ring (`story_state.phone_plan_outcomes`, ≤ 150 codes, `since`); the cue matches a short list of phrasings only (`plans.js strongCue`), so a turn in his own mix of languages isn't seen. A scene is checked for its decision and its sheet's `afterwards` lines, never its prose. `salary_once` flags a duplicate, not a missed salary.
- **When** — facade `afterTick` → `sweepTick`: once a night (`nightDue`: he is asleep after 18:00, or the first tick after midnight; several missed nights = one run), never in a simulation (a sim has no facade `afterTick`). A failure logs a code and marks that night tried, so it can't repeat on every tick. On demand: SWEEP NOW. Window: since the last run less a day, at most 14 days; on demand always 14 days. Appends nothing to `world_events`, calls no model. 20 ms on 45 simulated days.
- **Storage** — `story_state` keys `sweep_findings` (`{lastNight, lastRunAt, findings ≤ 100, ruleErrors?, recoveredAt?, durationMs}`) and `sweep_dismissed` (`[{fp, at, by}]` ≤ 300), each up to 64 KB (`STATE_JSON_LIMITS`), through the story facade (`sweepStateRead/Write`). No migration: findings are derived, a re-run rebuilds them. A finding not seen again inside the window goes; an older one stays until it ages out (14 days) or one of its events leaves his life; a dismissed fp never returns. A corrupt value reads as `corrupt: true`, never throws, and the next run rebuilds it (a corrupt dismissed list is lost: those findings can come back).
- **Dashboard** — dashboard only (owner decision), nothing is sent anywhere. `GET /api/life/alerts`, `POST /api/life/alerts/:fp/dismiss` (WRITE_LIMIT, audited `life.alert.dismiss` with fp + rule), `POST /api/life/alerts/run` (4/min, audited `life.alert.run` with the count), both readonly + CSRF. `/api/status` `life.alerts` = the open count (topbar badge). Panel: Life · Now, PLOT HOLES.
- **Rehearsal** — `node scripts/sweep-dry-run.js --source <db> [--days 14]`: a VACUUM INTO copy, read only, prints the findings (`scene_afterwards` not run there). Run it from the install whose `world.json` matches the source DB: the world comes from the tree, not the copy.
- **Tests** — `life-tests/70-sweep-rules` (each rule on real event shapes + its look-alike), `71-sweep-live` (when it runs, the café charge, revert / rewind / redaction, dismiss, downtime, sick + moved home, interview, corrupt value, failing store), `73-sweep-routes`, `arcs-tests/99-sweep-story`, `test:dashboard` `sweep:` / `thought:`.

## Thought vs deed

`src/life/thoughtDeed.js`, pure, no storage, no model. `life.thoughtDeed({date})` → `GET /api/life/thought-deed?date=YYYY-MM-DD` → Life · Day, THOUGHT VS DEED. One row per decision active that local day (opened, leaned, committed, reversed, expired, or its outing), with its whole history, so a decision over two days shows on both (`spansDays`): `"leaning stay (0.72)… went anyway (deadline draw)"`. `deed.cause` is the true one in code words (`draw lean early owner adopted text reply goal`, or the expiry reason); `went` comes from the log, not from the commit (true / false / null while it is still ahead). A plan made in a chat (`planEdits.chatMadeDecision`) reads "a plan from a chat"; a lean a chat caused is marked `fromChat`, a chat-nudged commit `nudged`; no option label of a chat's plan, no subject, no JID on any row. Test: `life-tests/72-thought-deed`.
