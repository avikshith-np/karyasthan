# Instagram reels

Detail moved out of CLAUDE.md (2026-11-02, the file passed Claude Code's size limit). Keep this file current when the feature changes.

The bot has his own Instagram account on a dedicated Android phone (Android 11+) and is a member of the owner's Instagram group. A few times a day he browses Reels in character, likes what fits his taste, and queues the best for the group. Design + Phase 0 findings: `specs/005-instagram-reels/plan.md`.

- **Device guard (hard rule: ADB controls ONLY `com.instagram.android`)** — `src/instagram/device.js` is the only door to the phone: named operations only (no generic shell), Instagram must be in front before every input/capture (re-checked after captures), a foreign app or the lock screen throws `ForeignAppError` and the session ends **without touching it** (no BACK/HOME), intents are Instagram-scoped (launch by component `.activity.MainTabActivity`; URLs allow-listed), `tapNode()` refuses buttons that hand off to other apps (share sheet's WhatsApp / system Share / Download / Add to story…), every command is pinned `adb -s` to the phone resolved from `IG_DEVICE_SERIAL`+`IG_DEVICE_MODEL` (the Nothing call-gateway phone is never addressed) and logged (`ig_device_log`, dashboard Device log). Only non-Instagram commands: wake/sleep, battery, getprop, focused-window read. Clips are recorded by scrcpy as a pure recorder (`--no-control`); OxygenOS 12 has no `screenrecord`.
- **Per reel** (`src/instagram/session.js`), `IG_WATCH_MODE=live` (default): for the whole session scrcpy streams screen + audio (`device.startScreenStream`, held back ~1 s and released only after a later foreground check confirms Instagram was still in front) into **Gemini Live** (`liveWatch.js`, automatic VAD off: each reel is a manual activity; reports arrive as tool calls `report_first_look`/`report_full`; output audio discarded; sliding-window compression + resumption on goAway). ~3 s after a reel lands → first look → Jev "worth watching?" + hazard nouls (`judge.js`) → most reels swiped at ~5–6 s; promising ones keep streaming → full report at ~12 s → Jev humour/fit scores, hazards (politics, religion, NSFW, violence, scam, cruelty, tragedy), ad → **the action is decided in code** (fail closed). Live perceives, Jev decides. `IG_WATCH_MODE=clip` (and the fallback when Live can't start or a report times out): one screenshot → Gemini quick description → if promising, record a 15 s clip → full description. Likes capped per day; strong reels are **Saved in Instagram** = the share queue (a reel's link can't be read on the phone — the clipboard is off limits). Every reel is logged in `ig_reels` with its description (FTS-searchable). Captions/descriptions from Instagram are untrusted → `sanitizeWebContent`.
- **Jev** (`src/brain/jev.js`) is TypeSafe's System One decision model via OpenRouter `POST /api/v1/systemone` (OpenRouter key). It returns typed answers + probabilities + confidence; it does not generate text or read audio/video — Gemini describes, Jev judges, the existing LLM writes the caption (`caption.js`: persona voice, printable ASCII only because `input text` can't type emoji/Malayalam script, postProcess + quality gate, `[SKIP]` → no caption).
- **Sharing** goes through Instagram's own share sheet: search `IG_GROUP_NAME`, require exactly one exact-name row that looks like a group, verify "<group> Chat selected", type caption, Send. `DRY_RUN` stops before Send. `approve-each` (default): the dashboard queue's APPROVE & SEND (`shareFromQueue`: refused 409 unless the reel is queued/approved/failed and the daily cap allows; the approval, caption and audit are written only after those checks) opens Search → Saved → the reel (opened items are checked by account; two by the same account among the first six → refused, the feed viewer shows nothing to tell them apart) → shares → un-saves. `auto`: strong reels are shared in-session after warmup (`IG_WARMUP_DAYS`), within `IG_SHARES_PER_DAY`.
- **Group chat** (`src/instagram/chat.js`, skill `instagram-chat`, boot default `IG_CHAT_ENABLED`) — every `IG_CHAT_POLL_MINUTES` while awake and after each browsing session he opens the Messages inbox and, **only if the group's row is unread**, that one thread (no other chat is ever opened). `screens.parseThread` infers senders like a person reads it (right-aligned = his, a username label starts someone's run, "X replied to you" names the next bubble; quoted content and reaction chips skipped). New messages go to `ig_messages`; reels members sent are opened, recorded (10 s clip) and described, then judged by Jev. A mention of his name/aliases (prefix match, so "Karyasthaa" counts) or a reply to him always gets a reply; otherwise Jev chooses reply / react (double-tap heart) / ignore. Replies: persona voice + the linked members' WhatsApp profiles → postProcess → quality gate → Latin-script text, `IG_CHAT_MAX_REPLIES_PER_HOUR`; `DRY_RUN` types then deletes. The group's People screen is read daily into `ig_members`; the dashboard links each member to a WhatsApp person (`person_jid`). Group-admin tools, calls, follow/add, camera/gallery and voice buttons are on the driver's never-tap list.
- **Phone lock** — `src/instagram/phoneLock.js` is a cross-process lock (`data/instagram/phone.lock`) taken by sessions, queue shares, chat checks and `ig-probe.js`, so two processes never drive the phone at once. A live pid's lock is held for up to 6 h (only pid reuse after a reboot makes it stale); a dead pid's is taken over at once. In-process, `withPhone()` (session.js) also wakes, refuses a lock screen and launches Instagram.
- **Taste card** — `src/personality/taste.json` (gitignored, per install; generated once from identity by `ensureTasteCard()` at `startInstagram()` when a phone is configured — clerk call `ig.taste`, retried next boot on failure —, editable on the dashboard; `taste.example.json` is the committed fallback).
- **On/off** — the `instagram-reels` manifest skill is the master switch for AUTOMATIC sessions (`scheduler.js`: `IG_SESSIONS_PER_DAY` random times outside sleep hours, ≥75 min apart). The dashboard Browse button (5/10/15 min, optional "allow sharing this session") and queue approvals work regardless; both respect daily caps, open alerts and a running session. An Instagram security check / block screen raises a dashboard alert and pauses everything until cleared.
- **Phone setup** — Screen lock **None**, all three animation scales **off** (uiautomator otherwise reports "could not get idle state"), Do Not Disturb, Instagram permission prompts pre-answered, no personal accounts. Wireless debugging turns itself off on Wi-Fi changes/reboots — USB or `adb tcpip` is steadier.
- Test with `npm run test:instagram` (no phone). End-to-end runs should use a scratch DB + `DRY_RUN=true` — the live `.env` has `DRY_RUN=false`.
