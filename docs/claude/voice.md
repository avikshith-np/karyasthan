# Voice notes & imitate-voice

Detail moved out of CLAUDE.md (2026-11-02, the file passed Claude Code's size limit). Keep this file current when the feature changes.

- **TTS** — `src/brain/voiceGen.js`. 3.8+ TTS models (`gemini-3.8-flash-tts`) are only served by the **Interactions API** (`POST /v1beta/interactions`, `audio/l16` → raw PCM); `*-preview` models use the legacy `generateContent` path. 3.8 speaks input **verbatim**, so delivery goes in `speech_metadata.style` (never in the text). `VOICE_NOTE_VOICE` may be a prebuilt name or a per-project custom `voice_…` id (Voice Design). One retry on 5xx/timeout, then `VOICE_NOTE_FALLBACK_MODEL`/`_VOICE`; a fallback logs `voice_fallback`. Markers: `[VOICE: …]`, `[VOICE(mood): …]`, `[SING: …]`; a small whitelist of inline cues (`<laugh>`, `<sigh>`, `<short pause>`, …) is kept for TTS and stripped from text replies (`SPEECH_TAG_RE`).
- **Imitate-voice** — while imitating, voice notes use the target's own **cloned** voice (Voice Replication). Gates (`resolveImitationVoice` in `imitationState.js`): the `imitate-voice` manifest skill (boot default `IMITATE_VOICE_ENABLED`), the group's opt-in (`group_imitation.use_voice`, dashboard checkbox), an active `person_voice` row, and `IMITATE_VOICE_MAX_PER_SESSION` (resets per activation; 0 = no cap). Singing stays off while imitating. A cloned voice never falls back to another voice (text/nothing instead). The quality gate always runs on cloned-voice text with a harm note and **fails closed**.
- **Enrollment = consent** — Google requires the owner's natural sample (10–30 s) **and** their reading of a fixed consent statement, speaker-verified. Two paths, both only with the owner's own recordings: DM the bot `voice enroll [en|ml]` (`src/whatsapp/voiceEnrollment.js`, intercepted in `events.js` before debouncing; only fresh push-to-talk notes, no forwards; members of the bot's groups only), or upload on the dashboard person page (`POST /api/people/:jid/voice`, explicit consent confirmation). `voice test` DMs the owner a sample of their own clone. The dashboard force-voice button speaks in the clone when the group is imitating with the voice on (written as the target, same fail-closed gate; no singing). `voice delete` / `DELETE /api/people/:jid/voice` and a purge revoke at once and delete at Google (always allowed, even with the skill off); a failed Google delete leaves the row revoked with `revoke_reason` ending " · Google delete pending" (`voiceStore`), retried by the 6-hourly maintenance (`retryPendingVoiceDeletes`). The dashboard's default consent language comes from the persona's language (`defaultConsentLanguage`, via `/api/status` `voiceConsentLanguage`). Recordings are never stored; only the `voice_…` id. Re-enrolling deletes the previous voice at Google before its row is overwritten (a pending one before the new voice is created); a failed delete refuses the enrollment and keeps the old row. Voices of people who left every group are deleted by the 6-hourly maintenance. Test with `npm run test:voice`. Design: `specs/004-voice/plan.md`.
